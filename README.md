# 电脑清理大师 (PC Cleanup Master)

作者：**xiaomo945** · https://github.com/xiaomo945
仓库：**https://github.com/xiaomo945/pc-clean-master** · 不想装 Python 就直接下载 `dist/电脑清理大师.exe` 双击运行

一个零依赖（仅用 Python 标准库 + Tkinter）的 Windows 电脑清理工具，纯图形界面，全程点击操作。

当前版本：**v3.0.2** —— 清理流程「只弹一次窗」：点一键清理只有一次
「是否开始」确认，确认之后不再弹任何窗口，也不会再闪黑色控制台窗口。

### v3.0.2 追加修复：零黑框 + 只弹一次

**① 清理时刷刷刷闪黑框**

不是程序崩了，是子进程：PyInstaller `--windowed` 打出来的 GUI 没有控制台，
但 `subprocess.run(["cmd", "/c", "del"...])` 默认会给子进程新建一个控制台窗口。
分批删文件时每批弹一次，清回收站的 `powershell` 又弹一次。

统一加 `_NO_WINDOW_KW`（Windows `CREATE_NO_WINDOW` = `0x08000000` +
`STARTUPINFO` / `SW_HIDE` 双保险），覆盖全部 5 处：
`rd /s /q` 强删兜底、`del /f /q` 单文件兜底、批量 `del`、
`Clear-RecycleBin` 的 powershell、`command` 类清理项。

**② 弹窗次数**

| 环节 | v3.0.1 | v3.0.2 |
|---|---|---|
| 一键清理前置提示（扫描中 / 没扫 / 没可清项） | 弹提示窗 | 状态栏 + 日志，零弹窗 |
| 一键清理确认 | 1 次 | **1 次（保留）** |
| 清理完成 | 弹「完成」窗 | 顶部绿色结果条 + 状态栏 + 日志 |
| 手动「确认清理」 | 最多 5 连弹（风险项 / AI 模型 / 提权 / 手动挑选 / 最终确认） | **合并成 1 次**，所有风险说明汇总在同一窗口，信息一条不少 |
| 需要管理员权限 | 弹窗问是否重启提权，可能再拉起 UAC | 不弹窗；照常尝试删除，删不掉的在日志里逐条列出 |
| 用户主动点「以管理员身份重启」 | 1 次确认 + 系统 UAC | 不变（主动操作，不在清理流程里） |

确认弹窗里也写明了「这是本次唯一一次确认：点『是』之后不再弹任何窗口」。
结果条示例：`✓ C: 盘清理完成 · 已删除 563.7 MB（13 项） · 剩余 19.8 GB / 共 100.0 GB`。

### v3.0.1 追加修复：用户主目录不当垃圾

有用户看到 `windos\ 48.3 GB · 未识别用途的目录`，以为是系统文件想删掉。

- 那不是 `C:\Windows`（本机 `C:\Windows` 实测 **18.12 GB**），
  而是 **`C:\Users\windos`** —— 用户名恰好叫 windos，展开 `Users\` 后看到的是
  **当前登录账户的主目录**，实测 **48.61 GB**。
- 里面是 AppData 29.16 GB（Local 17.44 / Roaming 11.51）、Documents 4.77 GB、
  `.workbuddy-ai` 4.35 GB、`WorkBuddy AI` 3.25 GB、`.workbuddy` 2.83 GB、
  `.cache` 1.29 GB、桌面 0.97 GB，以及 **NTUSER.DAT（当前账户配置单元）**。
- 删掉不会损坏 Windows 系统文件，但会丢掉几乎全部个人数据、聊天记录、
  浏览器和软件登录态，并破坏当前账户配置（下次登录会重建配置文件，软件要重装重登）。

现在的处理：

| 项 | v3.0.0 | v3.0.1 |
|---|---|---|
| 说明文字 | 未识别用途的目录（可能是你的项目、软件或资料） | Windows 用户主目录（当前登录账户）：桌面、文档、下载、AppData… |
| 影响 / 建议 | 无法自动判断内容 | 写明整体删除的后果：`⛔ 已锁定 · 只能展开后挑缓存` |
| 能否整体勾选 | **能 ☑（危险）** | **不能，显示 `×`，点了也不勾** |
| `clean_item()` | 会 `rmtree` 整个 48 GB | 新增 `_is_whole_dir_blocked()` 最后一道闸，直接拒绝 |

硬锁范围：`<盘>:\Users`、`<盘>:\Users\<用户名>`、用户目录下的 `AppData`
及其 `Local` / `Roaming` / `LocalLow`，以及任何盘根目录下叫 `Windows` /
`WinNT` / `Windows.old` / `System32` 的目录。
**只锁目录整体**，深层缓存（`AppData\Local\Temp`、Chrome Cache、`C:\Windows\Temp`）
仍可正常清理，系统临时文件 / 更新缓存等既有类目不受影响。
`_browse_picks()` 也会过滤掉旧勾选状态里残留的这些路径。

### v2.9 的核心改动（E/F 数据盘）

**先说坏消息：E/F 盘真的没多少垃圾可清。**

用真实数据扫了一遍（E 盘 416GB 剩 9.8GB，F 盘 415.5GB 剩 19.3GB）：

| 盘 | 大头占用 | 性质 |
|---|---|---|
| E | 黑神话悟空 138GB、ComfyUI 模型 84GB、WSL 32GB、个人资料 15GB、Ollama 模型 9.2GB | 全是**不能删**的 |
| F | 三角洲行动 103GB、GTA5 44GB、`pagefile.sys` 60GB、Ollama 模型 6.2GB | 同上 |

旧版数据盘扫描器只认几条硬编码路径（`E:\Steam\...`），
实测 **E 盘只扫出 628KB、F 盘 129 字节** —— 等于完全没用。
但不是漏扫了几十 GB 垃圾，是这两个盘本来就被游戏和模型占满了。
**工具不该骗你说有 100GB 可清。**

v2.9 真正能安全清出来的：E 盘约 5.8GB、F 盘约 2.1GB
（ComfyUI 下载缓存、WorkBuddy 日志、pnpm 包仓库、360 浏览器缓存、三角洲着色器缓存等）。

**① 软件缓存知识库（约 60 条规则）**

按商业清理软件的思路，把「缓存」和「数据」彻底分开。每条规则都写清楚：
这个文件夹是做什么的、**清理后会影响哪些功能**、建议、风险等级。

结果区新增「**清理后会影响什么功能 / 建议**」一列，例如：

| 目录 | 清理影响 |
|---|---|
| `ComfyUI-Cache\download-cache` 2.2GB | 只影响以后重装/修复 ComfyUI 时会重下，不影响现在出图 |
| `Saved\PSOCache` 2.1GB | 下次进游戏首次加载卡几秒重新编译着色器 |
| `pnpm\files` 3.4GB | 以后 install 会重新下载依赖，现有项目不受影响 |
| `.venv` 3.9GB | **ComfyUI 会打不开**，要重建环境并重装几个 GB 的 torch |
| `ComfyUI-Shared\models` 84GB | **出图直接报模型不存在**，要重下几十 GB |
| `xwechat_files` 6.9GB | **聊天记录里的附件永久丢失** |

**② 四级分级，默认全不勾**

| 分组 | 含义 | 默认 |
|---|---|---|
| 可放心清理 | 自动重建的缓存：着色器、日志、字节码、下载缓存 | 不勾 |
| 清了要重新下载 | 包仓库、模型缓存；软件照常用但首次需联网 | 不勾 |
| 需你确认 | `.venv`/`node_modules`/下载目录，或内容无法自动确认 | 不勾 + 二次确认 |
| 不建议清理 | 游戏本体、AI 模型权重、聊天记录、WSL、个人备份 | **只读，不可勾** |

> v3.0 起类目名前的彩色圆点 emoji 已去掉（Tk 会渲染成黑方块，且容易被误认成单选按钮）。

**③ 根目录文件夹用途说明（v3.0 起可逐层展开）**

逐个说明 `E:\`、`F:\` 根目录下每个文件夹是什么、清理有什么影响。
实测 E 盘 79 个目录识别 57 个，F 盘 40 个识别 34 个；
**认不出来的明确写「未识别用途，默认保留」**，绝不因为名字陌生就当垃圾。
`pagefile.sys` 这类系统大文件也单独说明（F 盘 60GB，要在系统设置里改，删不掉）。
v3.0 起每个目录都能点箭头逐层展开，里面的子文件夹 / 文件可手动勾选后删除
（顶层目录本身仍不可整体删，详见上面的 v3.0 章节）。

**④ 软件占用总览（只读）**

按软件汇总「占了多少 / 可放心清多少 / 需确认多少 / 别删多少」，
一眼看清 `WeGame 游戏库 198.7GB 建议保留`、`ComfyUI 89GB 其中可清 5GB`。

**⑤ 层层保护，绝不随便删**

- 只有**明确命中已知缓存规则**的目录才会被列为可清理；没认出来的一律不作为可删项
- 模型权重 / 游戏资源包 / 聊天记录 / 个人数据 → `readonly`，界面显示「—」不可勾，
  `clean_item()` 里也显式拒绝，双保险
- 「⚡ 一键清理」显式排除所有 `sc_*` 软件缓存类目，永远只清系统安全垃圾
- 点「确认清理」时，弹窗**逐条列出你勾选的软件缓存会影响什么功能**
- 数据盘「大文件 >500MB」改为风险项，触发二次确认（里面全是游戏 Paks 和模型）
- 顶部第三个数字收窄为「软件缓存可清理」—— 旧口径把 `g_large` 里 298GB 的
  游戏资源包算进去，E 盘虚报 320GB，跟 v2.8 修掉的 89.8GB 是同一个病根

**⑥ 识别引擎的两个坑（已修）**

- 规则按「最贴近目录自身」匹配，而不是第一条命中：
  否则 `F:\WeGameApps\rail_apps\...\Saved\PSOCache` 会先命中 `rail_apps`
  被当成游戏本体，2.1GB 可清的着色器缓存就被吞掉了
- 父子去重只在**同一个分级内部**做：游戏本体（只读）里的着色器缓存
  （可清）必须照样列出来，不能被父目录一起屏蔽

### v2.8 的核心改动


**① 「预计释放 89.8GB，实际只释放 600MB」的根因找到了**

旧版把「最大的文件夹排行」里的 `C:\Users\windos`（46.8GB）这类**用户真实数据**
也算进了「可释放空间」。用户勾上后，这些文件大量被占用删不掉，
于是数字虚高 + 实际没效果。

v2.8 的做法：
- **空间分析类目全部改为只读** —— 只告诉你空间被谁占了，绝不计入可释放数字
- 顶部**三个数字分开摆**：`已勾选可释放` / `一键可清理` / `需你确认`
- 新增 **⚡ 一键清理**：只清安全类垃圾，点一下就有确定效果，不用逐项挑

**② 不再显示几万个文件**

| | 旧版 | v2.8 |
|---|---|---|
| 垃圾扩展名文件 | 15828 个文件 | **800 个目录组** |
| 长期未使用文件 | 11610 个文件 | **800 个目录组** |
| 空文件夹 | 5000 个 | **200 个目录组** |
| 模型里条目总数 | 32000+ | **4601** |
| 全部展开后树上的行 | 32000+ | **39** |

- 逐文件清单改为**按目录聚合**：一个目录组 = 「这个目录里的这批垃圾」，
  展开还能看到具体是哪些文件；删除时精确到组内那几个文件，同目录的其它内容不动
- 每个类目默认只渲染 **30 条**，剩下的折成「还有 N 项」按需点开加载
- 新增**应用维度归并**：不再列 `C:\Users` 这种大而无当的路径，而是像商业软件那样
  列出「Chrome 5.6GB / Ollama 3.1GB / 微信 1.7GB / .workbuddy-ai 4.3GB」

**③ 新增「安装包 / 更新残留 / 未完成下载」扫描**

认出 `xxx-updater\installer.exe`、`app_shell_cache_*`、`*.part` 这类纯白扔的空间。
本机实测一次就找出 **1.4GB**（WorkBuddy 更新器安装包 483MB + CUDA 包下载残留 370MB
+ 应用安装包缓存 356MB + 另一个更新器 169MB）。

**④ 清理更靠谱**

| 老毛病 | v2.8 怎么修 |
|--------|-----------|
| 整个删掉 `AppData\Local\Temp`，很多程序约定要往那儿写，目录没了直接报错 | 改成**清空内容但保留目录本身**（`dirclean`） |
| 批量删除按个数分批，路径一长超出 Windows 命令行 8191 字符上限，**整条命令静默失败、一个都没删** | 改成**按字符长度分批** |
| 一个被锁死的文件能把整个清理卡死 | 删除加**超时保护 + `rd /s /q` 兜底**，单项也不卡 |
| 清理完报「实际释放 0B」（后台还在写盘，磁盘差值不准） | 改成**逐项累加实际删掉的字节数**，并同时显示磁盘空间变化 |

**⑤ 商业清理软件的标准交互**

- **磁盘占用条**：一眼看出这个盘被占了多少、垃圾占多少、还剩多少
- **⚡ 一键清理按钮**：只清安全类（临时文件 / 更新缓存 / 回收站 / 浏览器缓存 /
  显卡着色器缓存 / 安装包残留…），绝不碰文档、照片、聊天记录和任何软件数据
- 清理完成后**如实报告**：删了多少字节、成功几项、失败几项、失败原因

## 它能扫到什么

### 一、按盘分组 + 已知垃圾类目（每盘都扫）
| 类别 | 风险 | 说明 |
|------|------|------|
| 系统临时文件 / 更新缓存 / 传递优化 / 错误报告 / 回收站 / 系统日志 | 🟢 安全·自动 | 直接清，无需确认 |
| 预读取 / 缩略图 / IE·Edge 临时文件 / 浏览器缓存 / 显卡着色器缓存 | 🟡 可选 | 默认不勾，按需 |
| 应用软件缓存(OneDrive/Teams/微信/QQ…) / 应用商店 / 字体 / 图标缓存 | 🟡 可选 | 默认不勾，按需 |
| 内存转储 / Windows.old / WorkBuddy 日志 | 🟡 可选 | 默认不勾，按需 |
| 下载旧文件·安装包(>60天) | 🔴 风险 | 确认后删 |
| 注册表·无效卸载项 / 失效启动项 | 🔴 风险 | 确认后删（仅系统盘 C） |
| 注册表·使用痕迹 | 🟡 可选 | 默认不勾 |

### 二、全盘文件扫描（所有盘通用 · **按目录聚合**）
这些类目会识别出所有符合条件的文件，**v2.8 起按「所在目录」聚合成目录组**，
一个组 = 「这个目录里的这批垃圾」，展开还能看到具体是哪些文件：

| 类目 | 说明 |
|------|------|
| 垃圾扩展名文件 | `.tmp/.log/.bak/.old/.dmp/.cache/~$` 等残留 |
| 大文件 (>500MB) | 列出来让你挑着删 |
| 长期未使用文件 (>1年) | 很久没改过的文件 |
| 重复文件 | 按内容哈希比对，内容完全相同的副本（展开该类目时才做哈希，不拖慢扫描） |
| 空文件夹 | 没有任何内容的目录 |
| 零字节文件 | 大小为 0 的空文件 |

> 聚合的意义：原来 15828 个垃圾文件铺在树上没法看，现在变成 800 个目录组，
> 一屏能看完，勾选和删除也快得多。删除时**精确到组内那几个文件**，
> 同目录的其它内容不会被动。
> 全盘扫描会**跳过 Windows / Program Files / ProgramData 等系统核心目录**，
> 不会列出无数系统 DLL/驱动（这些不是垃圾也不该动）。

### 三、磁盘空间分析（所有盘通用 · ⚪ 只读）
这一层**不看扩展名白名单，直接把整盘文件都盘一遍**，回答"我的空间到底被什么占用了"。
**v2.8 起这一整层全部改为只读** —— 它只告诉你空间被谁占了，**绝不计入可释放数字**：

| 类目 | 说明 |
|------|------|
| 系统 / 程序占用（只读） | Windows + 已装软件共占多少空间。帮你搞清"剩下的 80G 是什么" |
| 🤖 **AI / 开发工具缓存与模型** | 自动识别 AI 模型权重与开发缓存，**每一条都标明是什么**（见下） |
| 图片 / 视频 / 音乐 / 文档 / 压缩包 / 安装包·光盘镜像 / 其他文件 | 按类型归类，每类列出**体积最大的 300 项** |
| 最大的文件夹排行 | 按占用体积排序的文件夹（游戏本体、素材库、下载目录等） |
| 最大的文件排行 | 按占用体积排序的单个文件 |
| **应用维度归并**（v2.8 新增） | 像商业软件那样按应用列出：「Chrome 5.6GB / Ollama 3.1GB / 微信 1.7GB / .workbuddy-ai 4.3GB」，而不是 `C:\Users` 这种大而无当的路径 |

> 为什么改成只读？v2.6/v2.7 把 `C:\Users\windos`（46.8GB）这类**用户真实数据**
> 也算进了「可释放」，用户勾上后大量文件被占用删不掉 —— 于是出现
> 「预计释放 89.8GB，实际只释放 600MB」。只读化是根治这个问题。

### 四、🤖 AI / 开发工具缓存识别（v2.5 新增）
用户目录里最大的空间黑洞往往不是系统垃圾，而是 **AI 与开发工具留下的缓存**。软件会专门识别这些并告诉你**它到底是什么**：

| 识别到的东西 | 说明 |
|------|------|
| `AppData\Local\pnpm\store` | **pnpm 全局包仓库**（Node 依赖缓存，可重新下载） |
| `AppData\Local\npm-cache` | npm 下载缓存（可删，会重下） |
| `AppData\Local\pip\cache` | pip 下载缓存（可删，会重下） |
| `.ollama\models` | ⚠ **Ollama 本地大模型权重**（删了要重新 pull） |
| `.cache\huggingface\hub` | ⚠ **Hugging Face 模型缓存**（Transformers 下载的权重） |
| `ComfyUI\models` | ⚠ **ComfyUI / SD 模型权重**（checkpoint、LoRA、VAE） |
| `node_modules` | Node 依赖包目录（npm / pnpm install 可重建） |
| `site-packages` / `.venv` | Python 第三方库 / 虚拟环境（pip install 可重建） |
| `__pycache__` | Python 字节码缓存（可安全删除） |
| `.git` | Git 仓库元数据（删了丢提交历史） |

- ⚠ 标记的**模型权重**在清理前会**额外弹一次确认窗**，并逐条列出是哪个模型。
- 其余都是「可重建缓存」——删掉不会丢数据，只是下次用到要重新下载。

### 五、每个文件的用途说明（v2.5 新增）
展开任意文件类目，每一行下面会用灰色小字写明**这个东西到底是什么**：
- 命中已知特征 → 直接说明（如「Ollama 本地大模型权重（删掉后本地 LLM 就没了，需重新 pull）」）
- 识别不出来 → **明确写「未知用途（.xxx 格式，无法自动识别）」**，绝不假装知道

### 风险规则
- **🟢 安全**：自动勾选并锁定，点「确认清理」即自动清。
- **🟡 可选**：默认**不勾**，你按需打勾。
- **🔴 风险**：默认不勾；勾选后点清理会弹窗**二次确认**才执行。
- **⚪ 只读**：纯信息展示，不参与清理，**也不计入可释放空间**。

### 关于顶部的三个数字（v2.8）
顶部显示**三个数字**，随你每打一个勾实时变化：

| 数字 | 含义 |
|------|------|
| **已勾选可释放** | 你**当前勾选**的项目能释放多少（去重后的真实值） |
| **一键可清理** | ⚡ 一键清理按钮会清掉多少（只含安全类垃圾） |
| **需你确认** | 其余可清理项的合计 —— 需要你自己逐项打勾 |

- 三个数字都做了**路径去重**：同一份空间不会被重复计算（例如「最大的文件夹」和「大文件」里包含同一个文件，或父目录和它内部的子文件同时被勾选）。
- 各**类目**之间也会互相重叠（同一个文件可能同时出现在「安装包」和「最大的文件」里），所以**类目大小相加会大于顶部数字**——顶部那个去重后的数字才是真实上限。
- 每一类都可以点开**逐项勾选**；条目太多时默认只渲染 30 条，点「还有 N 项」继续加载。
- 点类目行的方框 = 该类**全选 / 全不选**；安全类默认锁定为开（自动清理）。
- ⚪ 只读的「空间占用分析」（系统/程序占用、图片/视频/最大的文件夹…）**不计入**可释放空间 —— v2.4 之前会误算进去，导致数字虚高。
- 清理完成后弹窗显示的是**实际删掉的字节数**（逐项累加），并同时显示磁盘剩余空间变化。
- 被系统锁定删不掉的文件（如 `pagefile.sys` 页面文件、休眠文件、正在使用的文件）会**如实显示"跳过/失败"**，不会再谎报"已清理"。这类系统文件 v2.2 起已从扫描列表中排除。

## 使用方法

### 方式一：直接运行（需装 Python）
右键「以管理员身份运行」打开 PowerShell，进入本目录：
```powershell
python clean_master.py
```

### 方式二：打包成单文件 exe（推荐分发）
```powershell
pip install pyinstaller
pyinstaller --onefile --windowed --name "电脑清理大师" clean_master.py
```
生成 `电脑清理大师.exe` 在 `dist\`，双击即用，**发给朋友也能直接跑**。

> ⚠ **不要加 `--uac-admin`**（v2.7.1 起已去掉）。加了之后每次双击都强制弹 UAC 提权窗，
> 被安全软件拦掉或用户点「否」时，就表现为「双击没反应 / 闪退」—— 其实程序本身完全正常。
> 现在改成**按需提权**：顶部有「以管理员身份重启」按钮，只有真要清注册表(HKLM)
> 或系统目录时才提示你重启一次。

## 交互流程
1. 打开软件 → 顶部显示当前盘剩余空间、是否已管理员运行。
2. 选「**盘符**」下拉（C/D/E/F…） → 点「**扫描此盘**」（只扫这一个盘，快）。
   想一次扫完所有盘就点「**扫描全部盘**」。
3. 扫描完成 → 中间出现**磁盘占用条**（一眼看出空间被谁占了）+ 顶部三个数字，
   下面按 **分组 → 类别 → 文件** 三层展开。
4. 想立刻见效 → 点「**⚡ 一键清理**」，只清安全类垃圾（临时文件 / 更新缓存 /
   回收站 / 浏览器缓存 / 显卡着色器缓存 / 安装包残留…），**绝不碰文档、照片、聊天记录**。
5. 想自己挑 → 点类目行的 `☐ / ☑`（或点名称）全选 / 全不选，
   点左边箭头或双击展开后逐项勾；顶部「已勾选可释放」实时变化。
   **大目录**：在「根目录文件夹用途说明」里点箭头逐层展开，
   勾里面的子文件夹 / 文件 → 会单独弹一次「永久删除、不可恢复」的强确认。
6. 点「**确认清理**」→ 若有风险项 / 软件缓存 / 手动挑选的数据，分别弹窗确认 →
   定量进度条 + 逐条日志 → 完成弹窗显示**实际释放空间** + 成功/失败项数 + 剩余空间刷新。
7. 需要清理其他盘 → 切换盘符，重新扫描再清理即可。

### 扫描进度与停止（v2.4+）
- **实时进度**：状态栏每秒刷新「已扫描 N 个文件 · 已统计 X GB · 当前目录」，日志每 8 秒给一条，绝不会看着像卡死。
- **■ 停止按钮**：扫描/清理进行时出现在右上角，一点立刻中断。
- **逐盘出结果**：C 盘扫完马上就能看 C 盘结果，不用等 E/F 盘跑完；此时可以自由切换盘符查看。
- **停止不丢结果**：中途停止时，已经统计到的部分会照常显示，随时可以清理。
- **单遍扫描**：所有清单（垃圾/类型归类/最大文件夹/空文件夹）共用**同一次全盘遍历**，比早期版本快 2~3 倍。
- **多线程并行（v2.5）**：磁盘 I/O 是瓶颈，扫描改为**多线程并行**处理，实测比单线程快 2~4 倍。

> 扫描速度实测（v2.8，本机 C 盘 72 万文件）：**12.5 秒**跑完，扫描字节 85.3GB，
> 与磁盘已用 88.3GB 吻合。大几百 GB 的数据盘含大量小文件（游戏、node_modules）会慢一些，属正常现象。

> 建议扫描前关闭正在跑的大软件（浏览器、游戏），避免个别临时文件被占用而删不掉（会被自动跳过，不影响其他项）。
